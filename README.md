# ScamShield — Frontend

ScamShield는 화상 통화 중에 상대가 보이스피싱을 시도하는지 실시간으로 판단해, 보호받는 사람에게 확인 질문과 경고를 띄워 주는 서비스다. 2026-2 인하대학교 컴퓨터공학과 캡스톤 프로젝트다.

## 왜 만드는가

보이스피싱은 통화가 끝난 뒤 알아차리면 이미 늦다. 송금이나 앱 설치는 통화 도중에 일어난다. 그래서 통화가 이어지는 동안 대화를 듣고, 위험해지는 순간 바로 알려 주는 것을 목표로 한다.

사기 수법은 일반 전화에서 영상 통화와 화상회의로도 옮겨 가고 있다. 기관을 사칭한 사람이 화면에 나오면 의심하기가 더 어렵다. 우리는 일반 전화망 대신 브라우저 화상 통화를 무대로 삼는다. 브라우저 화상 통화는 양쪽 음성을 서버가 직접 받을 수 있다.

## 무엇에 집중하는가

| 축 | 집중하는 것 | 위치 |
|---|---|---|
| 통화 | 브라우저끼리의 1:1 화상 통화(WebRTC) | 이 레포, BE |
| 화면 | **통화를 방해하지 않으면서** 경고와 확인 질문을 띄우고, 사용자의 답을 다시 판단에 반영한다 | 이 레포 |
| 실시간 처리 | 양쪽 음성을 화자별로 글자로 바꾸고, 빠짐·중복 없이 순서대로 판단에 넘긴다 | [BE_ScamShield](https://github.com/M4-Scamshield/BE_ScamShield) |
| 판단·대응 | 통화 상태를 기억하는 멀티 에이전트(LangGraph): 의심 → 확인 질문 → 외부 조회 → 경고 | [scam-agent](https://github.com/M4-Scamshield/scam-agent) |

## 이 레포가 맡는 것

- **통화 화면**: 방에 들어가 상대와 화상 통화를 한다.
- **탐지 켜기**: 보호받는 사람이 탐지를 켜면 내 목소리와 상대 목소리를 따로 서버로 보낸다. 누가 한 말인지 구분돼야 판단할 수 있기 때문이다.
- **경고·확인 질문 패널**: 서버가 보내는 위험 단계, 확인 질문("어느 기관 누구인지 물어보세요" 등), 경고를 통화 화면 옆에 보여 준다. 사용자가 받은 링크나 번호를 입력하면 다음 판단에 쓰인다.

## 지금 되는 것 / 아직 안 되는 것

**되는 것**
- 1:1 화상 통화와 탐지 켜기 → 확인 질문 → 답 입력 → 경고까지 한 흐름

**아직 안 되는 것**
- 세 명 이상의 화상회의
- 서버가 재시작됐을 때 자동으로 다시 연결하기
- 서로 다른 모바일망끼리의 통화 연결(TURN 서버 없음)

**앞으로 검토하는 방향**
- 여러 명이 한 사람을 압박하는 화상회의형 사기
- 이미 쓰고 있는 화상회의 서비스에 붙이는 방식(브라우저 확장)

## 실행

```sh
npm ci
npm run dev   # http://localhost:5173 — BE(8080, 8081)가 떠 있어야 한다
```

마이크는 `localhost` 또는 `https` 주소에서만 켜진다.
