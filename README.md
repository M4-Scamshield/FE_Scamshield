# ScamShield — Frontend

ScamShield는 화상 통화 중에 상대가 보이스피싱을 시도하는지 실시간으로 판단해, 보호받는 사람에게 확인 질문과 경고를 띄워 주는 서비스다. 2026-2 인하대학교 컴퓨터공학과 캡스톤 프로젝트다.

## 왜 만드는가

보이스피싱은 통화가 끝난 뒤 알아차리면 이미 늦다. 송금이나 앱 설치는 통화 도중에 일어난다. 그래서 통화가 이어지는 동안 대화를 듣고, 위험해지는 순간 바로 알려 주는 것을 목표로 한다.

사기 수법은 일반 전화에서 영상 통화와 화상회의로도 옮겨 가고 있다. 기관을 사칭한 사람이 화면에 나오면 의심하기가 더 어렵다. 우리는 일반 전화망 대신 브라우저 화상 통화를 무대로 삼는다. 브라우저 화상 통화는 양쪽 음성을 서버가 직접 받을 수 있다.

## 무엇에 집중하는가

| 축 | 집중하는 것 | 위치 |
|---|---|---|
| 통화 | 브라우저끼리의 최대 4인 음성 통화(WebRTC) | 이 레포, BE |
| 화면 | **통화를 방해하지 않으면서** 경고와 확인 질문을 띄우고, 사용자의 답을 다시 판단에 반영한다 | 이 레포 |
| 실시간 처리 | 양쪽 음성을 화자별로 글자로 바꾸고, 빠짐·중복 없이 순서대로 판단에 넘긴다 | [BE_ScamShield](https://github.com/M4-Scamshield/BE_ScamShield) |
| 판단·대응 | 통화 상태를 기억하는 멀티 에이전트(LangGraph): 의심 → 확인 질문 → 외부 조회 → 경고 | [scam-agent](https://github.com/M4-Scamshield/scam-agent) |

## 이 레포가 맡는 것

- **통화 화면**: 방에 들어가 상대와 화상 통화를 한다.
- **통화 중 채팅**: 하단 채팅 버튼을 누르면 통화 영역 오른쪽 아래에 작은 채팅 팝업이 열린다. 제목을 드래그해 통화 영역 안에서 이동하고, 왼쪽 위·오른쪽 아래 모서리를 드래그해 너비와 높이를 조절한다. 최소 크기는 320×300px이며, 통화 영역 자체가 더 작은 경우에만 화면 안에 맞춘다. 제목이나 모서리에 포커스를 두면 방향키(Shift로 큰 폭 조절)로도 사용할 수 있다. 닫았다 열어도 위치·크기·작성 내용을 유지하며, 화면 크기가 바뀌면 영역 안으로 맞춘다. 통화 화면과 분석 화면의 위치와 크기는 유지한다. 같은 방의 현재 참가자에게 WebRTC DataChannel로 직접 전송하며, 닫혀 있을 때는 새 메시지 수를 표시한다. 메시지는 최대 2,000자, 현재 브라우저의 통화 기록은 최근 500개까지 유지하고 통화 종료 시 초기화한다. 서버 저장·이전 메시지 재전송·채팅 내용 분석은 제공하지 않는다.
- **대화별 채팅**: 하나의 팝업에서 상단 목록으로 대화를 전환한다. `모든 참가자`를 선택하면 전체 메시지만, 이름을 선택하면 그 사람과 주고받은 메시지만 표시하고 선택한 대화로 전송한다. 작성 중인 내용과 읽지 않은 메시지 수는 대화마다 따로 유지한다. 다른 대화의 새 메시지는 목록과 채팅 버튼에 표시하며, 해당 대화를 열었을 때만 읽음 처리한다. 개인 메시지는 해당 참가자의 DataChannel에만 보내며 발신자의 기록에는 `받는 사람에게`, 수신자의 기록에는 `나에게`로 표시한다. 퇴장한 사람과의 대화 기록도 다시 열 수 있지만 전송은 막는다. 자동으로 전체 메시지로 바꾸지 않는다.
- **화자별 통화 내용**: 분석 결과 화면 오른쪽의 `실시간 통화 내용`에서 화자별 프로필과 발화를 확인한다. `대화 기록 | 참가자 이름 | …`을 눌러 전체 또는 특정 참가자를 선택한다. SSE `utterance` 이벤트의 `trackId`(참가자 ID)로 구분하며, 프로필에는 이름의 첫 글자를 사용한다. 필터는 화면 표시에만 적용하며, 분석에는 전체 발화를 사용한다. 위험 발화 바로가기를 누르면 전체 보기로 전환해 해당 근거를 표시한다.
- **근거 발화 선택**: 분석 결과의 `근거가 된 말 N개 보기`를 누르면 화자와 발화 미리보기 목록이 펼쳐진다. 원하는 항목을 선택하면 해당 대화 기록으로 이동하고 발화와 화자를 강조한다. 사기 수법별 근거와 이전 판단 이력에서도 같은 방식으로 탐색한다.
- **자동 탐지**: 통화에 입장하면 각 참가자의 마이크를 참가자 ID와 함께 분석 서버에 보낸다. 통합 헤더의 회의룸 이름·실시간 위험도·AI 분석 탭으로 화면을 전환한다. 하단 통화 도구 바에서 참가자 수 옆의 `실시간 보호` 스위치로 음성 분석을 켜거나 끌 수 있으며, 통화·카메라·마이크는 유지한다. 분석을 끄면 현재 분석 이력은 초기화된다.
- **실시간 분석 화면**: 상단 통합 헤더의 회의룸 이름·실시간 위험도·AI 분석 탭으로 통화와 분석 화면을 전환한다. 하단에는 방패 버튼을 두지 않는다. 참가자 타일은 분석 화면에서 숨기지만 통화 세션·카메라·마이크·상대 음성 재생은 유지한다. 상단에는 로고와 `ScamShield`를 표시하고 왼쪽 35%에는 원형 상태 표시·위험도·감지 수법 수를, 오른쪽 65%에는 실시간 위험도 그래프를 배치하고 화면 높이에 맞춘다. 상단 가로 게이지는 표시하지 않는다. 모바일에서는 상태 표시 위, 그래프 아래로 배치한다. 분석 컨테이너와 그래프의 카드 배경·테두리·둥근 모서리를 없애 회의룸 배경으로 연결하고, 중첩된 좌우 여백과 최대 너비 제한 없이 제목·탭·얇은 구분선으로 정보를 나눈다. 페이지를 스크롤하지 않고 하단 통화 도구를 사용할 수 있다.
- **실시간 분석 결과**: 통합 헤더에서 `AI 분석` 탭을 누르면 AI 결과(좌)와 실시간 통화 내용(우)을 표시한다. 원형 상태 표시와 그래프는 실시간 위험도 탭에 두고, AI 분석에는 경고·판단 근거·수법·대응 안내·이전 판단만 보여 준다. 위험이 감지되지 않은 경우 짧은 안내 문구를 표시한다. 분석값이 없거나 연결 확인 중일 때는 안전으로 표시하지 않는다. 긴 결과와 대화 기록은 각 영역 안에서 스크롤한다. 새 결과는 `AI 분석` 탭에 점으로 표시하며 `실시간 위험도` 탭으로 현재 상태·그래프로 돌아갈 수 있다. 선택한 탭에는 민트색 밑줄을 표시하고 방향키·Home·End로도 전환할 수 있다. 원형 링은 계속 회전하고 배경 파형의 진폭은 선마다 다른 주기로 변한다. 동작 줄이기 설정에서는 정지한다. 모바일에서는 두 영역을 위아래로 배치한다.
- **시간별 위험도**: 기존 상태 API의 점수와 SSE 경고를 브라우저 수신 시각 기준으로 기록한다. 기존 경고 우선 점수 정책을 유지하며, 조회가 실패한 구간은 선으로 연결하지 않는다. 그래프에서 마우스나 방향키로 시점별 점수를 확인할 수 있다. 같은 점수 구간은 양 끝을 남기고 최대 1,200개 지점까지 유지한다. 분석을 끄거나 통화를 나가거나 새로고침하면 이력은 초기화된다. 서버 판단 시각에 맞춘 공유 이력·복원에는 별도의 서버 이력 API가 필요하다.
- **경고·확인 질문**: 분석 결과에서 서버가 보내는 위험 단계, 확인 질문("어느 기관 누구인지 물어보세요" 등), 경고를 보여 준다. 사용자가 받은 링크나 번호를 입력하면 다음 판단에 쓰인다.
- **위험 경고 배너**: 분석 중 처음 `WARN` 경고가 오면 통화방 상단에 붉은 배너를 표시한다. 배경을 가리거나 포커스를 이동하지 않으며, 닫기와 `실시간 분석 결과 보기` 버튼을 제공한다. 결과 보기 버튼은 통합 헤더의 실시간 위험도 탭을 활성화하고 원형 상태·그래프 화면을 연다. 닫아도 분석과 통화는 계속되고 같은 분석 세션의 경고 갱신에는 반복해서 뜨지 않는다. 배너 배경은 2초 주기로 밝기가 변하며, 동작 줄이기 설정에서는 정지한다. 근거 발화로 확인되는 현재 통화 중 상대방 영상은 빨간 테두리로 표시하며, 알림을 닫아도 해당 경고가 유지되는 동안 강조한다. 화자를 확인할 근거가 없으면 임의로 표시하지 않는다. 신고·상담 번호 112·1332는 [정부 안내](https://www.korea.kr/news/policyNewsView.do?newsId=148933209)를 따른다.

## 지금 되는 것 / 아직 안 되는 것

**되는 것**
- 최대 4인 음성 통화와 탐지 켜기 → 확인 질문 → 답 입력 → 경고까지 한 흐름

**아직 안 되는 것**
- 5명 이상 통화, 영상 통화
- 서버가 재시작됐을 때 자동으로 다시 연결하기
- 서로 다른 모바일망끼리의 통화 연결(TURN 서버 없음)

**앞으로 검토하는 방향**
- 여러 명이 한 사람을 압박하는 화상회의형 사기
- 이미 쓰고 있는 화상회의 서비스에 붙이는 방식(브라우저 확장)

## 실행

```sh
npm ci
npm run dev   # http://localhost:5173
```

마이크는 `localhost` 또는 `https` 주소에서만 켜진다.

### 개발용 API 서버 선택

설정이 없으면 API는 `http://localhost:8080`, 분석은 `http://localhost:8081`로 연결한다. 이때는 본인 PC에 두 백엔드 서버가 실행 중이어야 한다.

로컬 백엔드 대신 AWS 서버를 쓰려면 프로젝트 루트에 `.env.local`을 만들고 다음을 넣는다.

```dotenv
API_PROXY_TARGET=https://boostad.site
ANALYSIS_PROXY_TARGET=https://boostad.site
```

`.env.local`은 Git에서 제외되어 다른 작업자의 설정에 영향을 주지 않는다. 로컬 서버를 사용하는 작업자는 `.env.local` 없이 실행하거나 `.env.example`을 복사해서 사용하면 된다. API와 분석 서버를 각각 다른 주소로 설정할 수도 있다.

주소를 변경한 뒤에는 `npm run dev`를 재시작한다. HTTP와 WebSocket이 함께 같은 대상 서버로 연결되며, HTTPS 주소는 WebSocket에서 WSS로 연결한다. 브라우저의 요청 주소가 `localhost:5173`으로 보여도 Vite가 지정한 백엔드로 전달한다.

이 설정은 Vite 개발 서버의 프록시 설정이다. 빌드된 사이트를 배포할 때는 호스팅 서버의 `/api`, `/ws` 라우팅 설정을 사용한다.
